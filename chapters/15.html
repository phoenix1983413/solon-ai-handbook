15.1 理论讲解

15.1.1 研发效能的 AI 化转型

行业现状： - 代码库规模膨胀：百万行级代码库成为常态 - 技术债务累积：平均每个项目有 20-30% 的代码需要重构 - 知识断层：核心开发者离职带走关键知识 - 审查瓶颈：资深工程师 30-50% 时间花在代码审查上

AI 赋能研发效能的三个层次： 1. 辅助层：代码补全、文档生成、注释提取 2. 审查层：自动代码审查、安全漏洞扫描、性能建议 3. 智能层：架构推荐、技术债务评估、跨项目复用

15.1.2 代码智能的核心技术

1. LSP（Language Server Protocol）

  • 提供代码补全、跳转定义、查找引用、诊断错误
  • 支持 Java/Go/Python/TypeScript 等主流语言
  • Solon-AI 的 solon-ai-talents 中包含 LSP Talent

2. AST（抽象语法树）分析

  • 解析代码结构（类/方法/变量/注释）
  • 识别设计模式、代码坏味道
  • 计算圈复杂度、代码行数等度量指标

3. 代码语义索引

  • 基于代码结构 + 注释 + 变量名
  • 支持自然语言查询（"查找所有处理用户登录的代码"）
  • 结合 Lucene 实现全文检索

4. 代码 Diff 与变更分析

  • 识别新增/删除/修改的代码行
  • 分析变更影响范围（依赖的类/方法）
  • 生成变更摘要

15.1.4 关键技术决策

Q1：本地代码库 vs Git 远程仓库？

方案 优点 缺点 适用场景
本地代码库 实时性好、隐私安全 需部署索引服务 企业内部、保密项目
Git 远程仓库 集中管理、无需本地存储 网络延迟、权限复杂 开源项目、分布式团队

推荐：企业级采用本地代码库 + Git Webhook 增量同步

Q2：增量索引 vs 全量索引？

策略 优点 缺点 适用场景
全量索引 实现简单、一致性高 耗时久、资源消耗大 代码库 < 10 万行
增量索引 快速、资源消耗小 实现复杂、需处理依赖 代码库 > 10 万行

推荐：首次全量索引，后续 Git Webhook 触发增量索引

Q3：规则引擎 vs LLM 审查？

方案 优点 缺点 适用场景
规则引擎 确定性强、速度快 覆盖不全、维护成本高 规范检查（命名/格式）
LLM 审查 灵活、理解语义 不确定、成本高 架构/安全/性能审查

推荐：混合模式 - 规则引擎做前置过滤，LLM 做深度审查

15.2 实践练习

练习1：基于 LSP 的代码语义搜索

目标：使用 LSP 协议实现代码语义搜索

@Singleton
public class LspCodeSearchService {
    private final LspClient lspClient;
    private final LuceneCodeIndex codeIndex;

    @Inject
    public LspCodeSearchService(LspClient lspClient, LuceneCodeIndex codeIndex) {
        this.lspClient = lspClient;
        this.codeIndex = codeIndex;
    }

    public List<CodeSymbol> search(String naturalLanguageQuery) {
        // 1. 将自然语言转为代码符号查询
        // 例如："用户登录" → method:login, class:UserService
        SymbolQuery symbolQuery = parseQuery(naturalLanguageQuery);

        // 2. 在 Lucene 索引中搜索
        List<CodeSymbol> candidates = codeIndex.search(symbolQuery);

        // 3. 使用 LSP 获取详细上下文
        for (CodeSymbol candidate : candidates) {
            candidate.setReferences(lspClient.findReferences(candidate));
            candidate.setCallers(lspClient.findCallers(candidate));
        }

        return candidates;
    }

    private SymbolQuery parseQuery(String naturalLanguage) {
        // 使用 LLM 将自然语言转为符号查询
        ChatResponse response = chatModel.prompt(naturalLanguage)
                .system("你是代码搜索专家，将自然语言查询转为代码符号查询")
                .call();
        return SymbolQuery.fromJson(response.getMessage().getContent());
    }
}

关键工程细节： - LSP 通信基于 JSON-RPC（stdio 或 TCP） - Lucene 索引构建时提取代码结构（类名/方法名/注释）

练习3：代码生成上下文管理

目标：基于项目上下文生成代码

@Singleton
public class CodeGenerationContextManager {
    private final LuceneCodeIndex codeIndex;
    private final LspClient lspClient;

    public GenerationContext buildContext(String prompt, String filePath) {
        // 1. 提取当前文件的上下文
        CodeFile currentFile = lspClient.getFile(filePath);

        // 2. 检索相关代码片段
        List<CodeSymbol> relatedSymbols = codeIndex.search(prompt);

        // 3. 构建 Prompt
        StringBuilder context = new StringBuilder();
        context.append("项目上下文：\n");
        context.append("当前文件：").append(filePath).append("\n");
        context.append("当前包：").append(currentFile.getPackageName()).append("\n\n");

        context.append("相关代码：\n");
        for (CodeSymbol symbol : relatedSymbols) {
            context.append("- ").append(symbol.getQualifiedName())
                   .append(": ").append(symbol.getSnippet()).append("\n");
        }

        context.append("\n用户需求：").append(prompt);

        return GenerationContext.builder()
                .context(context.toString())
                .relatedSymbols(relatedSymbols)
                .currentFile(currentFile)
                .build();
    }
}

练习4：技术债务可视化

目标：分析并可视化代码库的技术债务

@Singleton
public class TechDebtAnalyzer {
    private final CodeIndex codeIndex;
    private final ComplexityAnalyzer complexityAnalyzer;

    public TechDebtReport analyze(String repoPath) {
        // 1. 圈复杂度分析
        Map<String, Double> complexityMap = complexityAnalyzer.analyze(repoPath);

        // 2. 代码重复检测
        List<DuplicateBlock> duplicates = detectDuplicates(repoPath);

        // 3. 依赖老化分析
        List<Dependency> outdatedDependencies = analyzeDependencies(repoPath);

        // 4. 生成报告
        return TechDebtReport.builder()
                .totalLines(codeIndex.countLines())
                .avgComplexity(complexityMap.values().stream().mapToDouble(d -> d).average().orElse(0))
                .highComplexityMethods(complexityMap.entrySet().stream()
                        .filter(e -> e.getValue() > 20)
                        .map(Map.Entry::getKey)
                        .toList())
                .duplicateBlocks(duplicates)
                .outdatedDependencies(outdatedDependencies)
                .build();
    }
}

模块1：代码索引服务

@Singleton
public class CodeIndexService {
    private final LuceneCodeIndex codeIndex;
    private final JGit gitClient;
    private final EventPublisher eventPublisher;

    // 全量索引
    public void fullIndex(String repoPath) throws Exception {
        long start = System.currentTimeMillis();

        // 1. 遍历代码文件
        List<CodeFile> files = scanCodeFiles(repoPath);

        // 2. 解析 AST
        List<CodeSymbol> symbols = new ArrayList<>();
        for (CodeFile file : files) {
            symbols.addAll(parseAst(file));
        }

        // 3. 建立 Lucene 索引
        codeIndex.index(symbols);

        long duration = System.currentTimeMillis() - start;
        log.info("Full index completed: files={}, symbols={}, duration={}ms",
            files.size(), symbols.size(), duration);
    }

    // 增量索引（基于 Git Webhook）
    public void incrementalIndex(GitPushEvent event) {
        // 1. 获取变更文件
        List<ChangedFile> changedFiles = gitClient.getChangedFiles(event.getCommitId());

        // 2. 只索引变更的文件
        for (ChangedFile file : changedFiles) {
            CodeFile codeFile = gitClient.getFile(event.getCommitId(), file.getPath());
            List<CodeSymbol> symbols = parseAst(codeFile);
            codeIndex.update(file.getPath(), symbols);
        }

        log.info("Incremental index completed: files={}", changedFiles.size());
    }
}

模块2：代码审查 Agent

@Singleton
public class CodeReviewAgent {
    private final DiffAnalyzer diffAnalyzer;
    private final SecurityScanner securityScanner;
    private final ChatModel chatModel;
    private final NotificationService notificationService;

    public ReviewResult review(GitPushEvent event) {
        // 1. 获取变更
        List<ChangedFile> changedFiles = diffAnalyzer.getChangedFiles(event);

        List<ReviewComment> comments = new ArrayList<>();

        for (ChangedFile file : changedFiles) {
            // 2. 规则审查
            comments.addAll(checkNaming(file));
            comments.addAll(checkSecurity(file));
            comments.addAll(checkPerformance(file));
        }

        // 3. LLM 深度审查
        ReviewSummary summary = llmDeepReview(event, comments);

        // 4. 发送通知（企业微信/钉钉）
        notificationService.sendReviewResult(event.getAuthor(), summary);

        return ReviewResult.builder()
                .comments(comments)
                .summary(summary)
                .build();
    }

    private ReviewSummary llmDeepReview(GitPushEvent event, List<ReviewComment> comments) {
        // 构造完整 diff 上下文
        String diff = diffAnalyzer.getDiff(event);

        ChatResponse response = chatModel.prompt(diff)
                .system("你是资深代码审查专家，请审查以下代码变更，关注架构、设计、可维护性")
                .call();

        return ReviewSummary.fromJson(response.getMessage().getContent());
    }
}

模块3：变更影响分析

@Singleton
public class ChangeImpactAnalyzer {
    private final LspClient lspClient;
    private final CallGraphBuilder callGraphBuilder;

    public ImpactReport analyze(ChangedFile file) {
        // 1. 获取变更的方法/类
        List<CodeSymbol> changedSymbols = extractChangedSymbols(file);

        // 2. 构建调用图
        CallGraph callGraph = callGraphBuilder.build(file.getRepoPath());

        // 3. 分析影响范围
        Set<CodeSymbol> affectedSymbols = new HashSet<>();
        for (CodeSymbol symbol : changedSymbols) {
            affectedSymbols.addAll(callGraph.getCallers(symbol));
            affectedSymbols.addAll(callGraph.getCallees(symbol));
        }

        // 4. 生成影响报告
        return ImpactReport.builder()
                .changedSymbols(changedSymbols)
                .affectedSymbols(affectedSymbols)
                .riskLevel(calculateRisk(affectedSymbols.size()))
                .build();
    }
}

模块5：Webhook 监听与调度

@Singleton
public class GitWebhookController {
    private final CodeIndexService indexService;
    private final CodeReviewAgent reviewAgent;

    @Post("/webhook/gitlab")
    public Result handleGitLabPush(@Body GitPushEvent event) {
        // 1. 验证签名
        if (!verifySignature(event)) {
            return Result.fail("Invalid signature");
        }

        // 2. 异步处理（避免 Webhook 超时）
        eventPublisher.publish(event);

        return Result.success("接受成功");
    }

    @Subscribe
    public void onGitPush(GitPushEvent event) {
        // 1. 增量索引
        indexService.incrementalIndex(event);

        // 2. 自动代码审查（仅针对 MR）
        if (event.isMergeRequest()) {
            reviewAgent.review(event);
        }
    }
}
