11.1 理论讲解

11.1.1 高级 RAG 技术

  • Hybrid Search：向量检索 + 关键词检索（BM25）
  • Query Rewriting：用户查询重写
  • Context Compression：上下文压缩
  • Multi-Hop RAG：多跳推理检索
  • Agentic RAG：Agent 自主决定检索策略

11.1.2 生产环境考量

  • 文档版本管理：支持增量更新
  • 权限控制：基于用户的访问控制（RLS）
  • 监控与日志：检索质量评估
  • 缓存策略：热点查询缓存

11.2 实践练习

练习1：混合检索

// 1. 向量检索
List<Document> vectorResults = vectorRepository.search(query, 20);

// 2. 关键词检索（Lucene）
List<Document> keywordResults = luceneRepository.search(query, 20);

// 3. 结果融合（RRF）
List<Document> fused = hybridSearch(vectorResults, keywordResults);

// 4. Rerank
List<Document> finalResults = reranker.rerank(query, fused, 5);

第11章 注意事项

  1. RRF 融合参数 k：Reciprocal Rank Fusion 中的 k 通常取 60，k 过大则权重趋近均匀，k 过小则 Top1 结果占主导，需要根据业务调优。
  2. Query Rewriting 边界：重写次数建议 1-2 次，过度重写（如 5 次以上）会引入噪声，反而降低检索精度。
  3. Context Compression 慎用：压缩会丢失细节，法律、医疗、金融等对精度要求高的场景建议保留完整上下文。
  4. 增量更新策略：文档版本更新时，建议按 doc_id 删除旧向量再插入新向量，不要直接覆盖，避免残留旧数据。
  5. RLS 实现位置：基于用户的访问控制（Row Level Security）需要在 Repository 层（如 PgVectorRepository）显式过滤，不是向量库原生支持。

第11章 实战作业

作业1：基础巩固

实现 Hybrid Search： - 向量检索：PgVector，召回 Top 20 - 关键词检索：Lucene，召回 Top 20 - RRF 融合（k=60），取 Top 10 - BGE-Reranker 精排，最终输出 Top 5

作业2：拓展应用

实现 Query Rewriting 增强： - 用户原始 query："RAG 是什么" - LLM 重写为 3 个角度："RAG 定义"、"RAG 工作原理"、"RAG 应用场景" - 三个 query 分别检索，结果去重后合并

作业3：动手实践

构建"法律文档智能问答"系统： - 上传合同/法规/判例 PDF - 检索时标注引用来源（文件名、页码、段落） - 识别并脱敏敏感信息（身份证号、银行卡号、手机号） - 提供"对比分析"功能：同时检索 2-3 份文档，输出异同点
