10.1 理论讲解

10.1.1 多 Agent 架构模式

模式1：层级式（Supervisor）
    ┌─────────────┐
    │ Supervisor  │
    └──────┬──────┘
           │
    ┌──────┼──────┐
    ▼      ▼      ▼
 Agent1 Agent2 Agent3

模式2：流水线（Pipeline）
    Agent1 → Agent2 → Agent3

模式3：合同网（Contract Net）
    Manager ← Bidders
           ↓
     Awarded Worker

模式4：黑板（Blackboard）
    ┌─────────────────┐
    │  Shared Blackboard │
    └─────────────────┘
           ▲
    Agent1 Agent2 Agent3

10.1.2 通信与同步

  • 消息传递：通过 TeamMessage 在 Agent 间传递
  • 状态共享：Blackboard 模式共享上下文
  • 结果合并：Supervisor 汇总子 Agent 输出

import org.noear.solon.ai.agent.graph.*;

public class GraphAgentDemo {
    public static void main(String[] args) {
        // 定义图
        Graph graph = Graph.builder()
                .node("classify", new ClassifyNode())
                .node("retrieve", new RetrieveNode())
                .node("generate", new GenerateNode())
                .edge("classify", "retrieve")
                .edge("retrieve", "generate")
                .build();

        // 执行图
        GraphResult result = graph.run(input);
        System.out.println(result.getOutput());
    }
}

练习2：人机协作（Human-in-the-Loop）

TeamAgent team = TeamAgent.of(chatModel)
        .name("approval_team")
        .protocol(TeamProtocols.HIERARCHICAL)
        .humanInLoop(true)  // 开启人工审批
        .agentAdd(workerAgent)
        .build();

// 当需要人工审批时，Agent 会暂停并等待
String result = team.prompt("请审批这份合同")
        .call()
        .getMessage()
        .getContent();

10.3 项目实战

实战任务：智能项目管理助手

实现一个多 Agent 协作的项目管理系统：

  • Planner Agent：分解任务，生成计划
  • Coder Agent：编写代码
  • Reviewer Agent：代码审查
  • Tester Agent：生成测试用例
  • Reporter Agent：生成进度报告

第10章 注意事项

  1. Graph 拓扑约束：节点（node）名称必须唯一，边（edge）的目标节点必须先定义，否则 Graph 启动会报 NodeNotFoundException。
  2. Human-in-the-Loop 阻塞模型：开启后 Agent 执行会阻塞等待用户输入，Web 场景需封装为异步接口（如 Mono/Flux），避免阻塞 Servlet 线程。
  3. TeamAgent.prompt() 同步阻塞：默认 prompt().call() 是阻塞调用，高并发场景建议使用 prompt().stream() 响应式流。
  4. Blackboard 并发安全：多 Agent 通过共享黑板（Blackboard）交换数据时，注意数据一致性问题，必要时加同步锁。
  5. 子 Agent 失败策略：默认行为是向上抛出异常终止整个 Team，需在 Supervisor 层显式捕获并决定是否重试或降级。

第10章 实战作业

作业1：基础巩固

实现一个"调研助手 Graph"： - 节点1（classify）：判断用户问题是"技术类"还是"商业类" - 节点2（retrieve）：根据分类检索不同知识库 - 节点3（generate）：生成结构化调研报告 使用 Graph.builder() 定义节点和边，执行 3 个不同 query。

作业2：拓展应用

实现带重试机制的 Agent 调用： - 子 Agent（如 Coder Agent）失败后自动重试 2 次 - 每次重试间隔 5 秒，并在 prompt 中注入前一次错误信息 - 记录重试次数和最终结果到日志

作业3：动手实践

实现"智能项目管理助手"（完整版）： - Planner：接收需求文档，生成 Task 列表（Markdown 表格） - Coder：根据 Task 编写代码（Java/Python） - Reviewer：审查 Coder 产出，给出修改意见 - Tester：编写单元测试用例（JUnit/pytest） - Reporter：汇总各阶段产出，生成项目周报 要求使用 HIERARCHICAL 协议，Supervisor 负责结果汇总。
