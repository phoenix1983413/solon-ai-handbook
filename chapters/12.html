12.3 项目实战

实战任务：企业 MCP 工具市场

实现： - 工具注册中心 - 权限管理（RBAC） - 调用统计与计费 - 版本管理

第12章 注意事项

  1. Gateway Talent 显式引入：McpGatewayTalent 位于 solon-ai-talent-gateway 模块，需单独引入依赖，不是 solon-ai 聚合包的一部分。
  2. 熔断超时配置：网关层的熔断策略需要根据 MCP Server 响应时间配置，建议默认 5 秒超时，失败阈值 3 次，熔断时长 60 秒。
  3. 全链路追踪：工具调用日志必须记录 request_id（或 trace_id），否则排查跨 Service 调用问题时难以串联日志。
  4. RBAC 粒度建议：权限控制建议到工具级别（如允许调用 get_weather 但禁止 delete_user），而非 Server 级别。
  5. 计费维度选择：计费模型建议按"工具调用次数"或"Token 消耗"计费，按 Server 注册数计费无法反映真实使用量。

第12章 实战作业

作业1：基础巩固

基于 McpGatewayTalent 实现一个简易 MCP 网关： - 注册 2 个 MCP Server（本地计算器 Server + 远程天气 Server） - 记录每次工具调用的 server_name、tool_name、params、result、cost_ms 到日志文件

作业2：拓展应用

为网关添加熔断机制： - 使用 Resilience4j 或 Solon 内置断路器 - 当某 MCP Server 连续失败 3 次，自动熔断 60 秒 - 熔断期间返回降级响应："工具暂时不可用，请稍后重试"

作业3：动手实践

实现 MCP 工具市场的 RBAC 权限管理： - 角色定义：admin（全部权限）、developer（开发工具）、analyst（查询工具） - 工具白名单：每个角色绑定允许调用的工具列表 - 中间件拦截：调用前校验用户角色是否有权调用目标工具 - 管理页面：可视化展示角色-工具矩阵，支持动态调整
