13.1 理论讲解

构建一个完整的智能客服平台，整合前面所有知识点：

功能模块： 1. 用户管理：用户注册、登录、会话管理 2. 知识库管理：文档上传、切分、向量化 3. 智能问答：RAG + Agent 混合问答 4. 工单系统：自动创建、分配、流转 5. 数据分析：问答质量评估、热点问题统计

13.2 实践练习

模块1：RAG 检索服务

@Controller
public class KnowledgeController {
    private final PgVectorRepository repository;
    private final ChatModel chatModel;

    @Inject
    public KnowledgeController(PgVectorRepository repository, ChatModel chatModel) {
        this.repository = repository;
        this.chatModel = chatModel;
    }

    @Post("/api/chat")
    public ChatResponse chat(@Body ChatRequest request) {
        // 1. 检索相关知识
        List<Document> docs = repository.search(request.getQuery(), 5);

        // 2. 构造增强 Prompt
        ChatMessage message = ChatMessage.ofUserAugment(request.getQuery(), docs);

        // 3. 调用 LLM
        return chatModel.prompt(message)
                .system("你是智能客服助手，请基于知识库回答用户问题。")
                .call();
    }
}

模块2：工单 Agent

public class TicketAgent {
    private final TeamAgent ticketTeam;

    public TicketAgent(ChatModel chatModel) {
        this.ticketTeam = TeamAgent.of(chatModel)
                .name("ticket_team")
                .protocol(TeamProtocols.HIERARCHICAL)
                .agentAdd(new ClassifyAgent())
                .agentAdd(new AssignAgent())
                .agentAdd(new ResponseAgent())
                .build();
    }

    public TicketResult process(String userQuery) {
        String result = ticketTeam.prompt("处理工单：" + userQuery)
                .call()
                .getMessage()
                .getContent();

        return JsonUtil.parse(result, TicketResult.class);
    }
}

模块3：AI Flow 工单流程

# ticket-flow.yml
id: ticket_processing
layout:
  - type: "start"
  - task: "@VarInput"
    meta:
      message: "请输入工单内容"
      varName: "ticket_content"
  - task: "@ChatModel"
    meta:
      systemPrompt: "你是工单分类专家，请判断工单类型（技术问题/业务咨询/投诉）"
      model: "qwen2.5:1.5b"
  - task: "@IfElse"
    meta:
      condition: "${output} == '技术问题'"
      then:
        - task: "@ChatModel"
          meta:
            systemPrompt: "你是技术支持，请提供解决方案"
      else:
        - task: "@ChatModel"
          meta:
            systemPrompt: "你是客服，请礼貌回复"
  - task: "@ConsoleOutput"

13.3 项目实战

Docker Compose 部署方案

# docker-compose.yml
version: '3.8'
services:
  app:
    image: your-company/smart-cs:latest
    ports:
      - "8080:8080"
    environment:
      - SOLON_AI_CHAT_DEFAULT_PROVIDER=ollama
      - SPRING_DATASOURCE_URL=jdbc:postgresql://pg:5432/cs_db
    depends_on:
      - pg
      - ollama

  pg:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_PASSWORD: password
      POSTGRES_DB: cs_db

  ollama:
    image: ollama/ollama:latest
    volumes:
      - ./models:/root/.ollama
    command: serve

项目部署检查清单

  1. 环境准备：Docker 20.10+、Docker Compose 2.0+、8GB+ 内存
  2. 模型准备：下载 qwen2.5:1.5b 和 bge-m3 到 Ollama
  3. 数据库初始化：创建 cs_db 数据库，启用 vector 扩展
  4. 配置文件：修改 application.yml 中的数据库连接和模型地址
  5. 启动服务：docker-compose up -d，观察日志确认所有服务健康
  6. 验证功能：访问 http://localhost:8080，测试问答和工单创建流程

第13章 注意事项

  1. 综合项目前置依赖：本章是前 12 章知识点的整合，建议逐章完成练习后再开始，跳章会导致知识点缺口难以衔接。
  2. 混合问答策略：智能客服优先走 RAG 检索 → 无答案再触发 Agent 深度检索 → 仍无答案转人工工单，三层递进。
  3. 工单时间线持久化：工单流转记录（创建、分配、回复、关闭）建议存入 PostgreSQL jsonb 字段，便于回溯和审计。
  4. 数据分析不要自造轮子：问答质量评估、热点统计建议直接接入 ELK 或 Prometheus，重复造轮子性价比极低。
  5. Docker 部署注意：depends_on 仅保证容器启动顺序，不保证服务就绪；建议在 App 启动脚本中增加健康检查（pg_isready、curl ollama:11434）。

第13章 实战作业

作业1：基础巩固

完成智能客服平台的最小可行版本（MVP）： - 用户通过 POST /api/chat 提问 - 后端优先查询 PgVector 知识库 - 有答案则返回，无答案则返回固定话术 - 前端使用 Vue/React 实现简单对话界面

作业2：拓展应用

在 MVP 基础上添加工单系统： - 当 RAG 无答案时，自动创建工单（类型：技术问题/业务咨询/投诉） - 使用 TeamAgent（ClassifyAgent → AssignAgent → ResponseAgent）自动处理 - 工单状态流转：待分配 → 处理中 → 已解决 → 已关闭

作业3：动手实践

完整部署智能客服平台到 Docker Compose： - 服务清单：App、PostgreSQL+pgvector、Ollama、Redis、Prometheus+Grafana - 配置健康检查脚本，确保依赖服务就绪后再启动 App - 接入日志收集（stdout → Loki 或 ELK），实现全链路追踪 - 编写 README.md，记录启动步骤、端口映射、默认账号密码

Q1: Solon-AI 和 LangChain4j 有什么区别？

特性 Solon-AI LangChain4j
框架依赖 Solon（轻量） Spring Boot（较重）
Agent ✅ ReAct + Team + Graph ✅
MCP ✅ 原生支持 ❌
Flow 编排 ✅ YAML ❌
Talents ✅ 17 个预置 ❌
社区活跃度 中等（国内） 高（国际）

Q2: 如何选择向量数据库？

场景 推荐 理由
学习/原型 InMemory / Redis 零配置
中小规模 pgvector PostgreSQL 生态
大规模（千万级） Milvus / Qdrant 高性能
已有 ES OpenSearch / ES 统一技术栈
云服务 DashVector / TCVectorDB 免运维

Q3: Ollama 适合生产环境吗？

  • ✅ 适合：小团队、内部工具、原型验证
  • ❌ 不适合：高并发、企业级 SLA
  • 替代方案：vLLM、TGI、DeepSeek 官方 API
