19.1 理论讲解

19.1.1 项目概述

面向公共安全领域的垂直大模型与行业智能体，融合警务大模型、技战法工厂、六维标签、时空计算、智能体编排等核心引擎。基于全域任务编排、可信数据协同、虚实融合训推、战法技能生产四大核心技术，具备业务系统操作接口，可直接转化为可执行指令，实现从"咨询问答"到"业务闭环"的跨越。

19.1.2 核心能力

1. 警务大模型引擎 - 基于 Solon-AI 的 ChatModel 能力，构建警务垂直领域大模型 - 支持多轮对话、上下文记忆、意图识别 - 集成 DeepSeek、Qwen 等国产大模型，满足等保要求

2. 技战法工厂 - 将民警实战经验抽象为可复用的"技战法"Skill - 支持可视化编排、版本管理、效果评估 - 基于 Solon-AI 的 Talents 能力插件体系扩展

3. 六维标签体系 - 人员标签：身份、行为、关系、风险、轨迹、资产 - 基于 RAG 知识库 + 向量化实现智能标签推理 - 支持标签动态更新、血缘追溯

4. 时空计算引擎 - 集成 PostGIS + 时空轨迹存储 - 支持时空范围查询、路径分析、热点发现 - 基于 Solon-AI Flow 实现复杂的时空计算编排

5. 智能体编排系统 - 基于 Solon-AI 的 Agent + Team Agent 能力 - 支持多智能体协作（分析 agent、预警 agent、报告 agent） - 基于 Graph orchestration 实现复杂任务流

6. 全域任务编排 - 基于 Solon-AI Flow 低代码编排 - 支持事件驱动、定时任务、人工触发等多种触发方式 - 可视化任务流设计器

7. 可信数据协同 - 支持 48+ 类数据源接入（公安网、互联网、物联网） - 数据脱敏、权限控制、审计日志 - 基于 RBAC + 数据权限实现细粒度访问控制

8. 虚实融合训推 - 仿真环境 + 真实环境联合训练 - 支持模型热更新、A/B 测试 - 基于 Solon-AI 的 RAG 能力实现知识增强

9. 业务系统操作接口 - 标准化业务接口（接处警、人口、案件、车辆等） - 支持直接调用业务系统 API，实现业务闭环 - 指令执行结果自动回写业务系统

19.2 实践练习

练习1：警务垂直大模型接入

目标：基于 Solon-AI 的 ChatModel，接入国产大模型，构建警务垂直领域对话能力。

步骤： 1. 创建 Solon-AI 项目，添加 solon-ai-chatmodel 依赖 2. 配置 DeepSeek / Qwen 国产大模型（需符合等保要求） 3. 构建警务领域提示词模板库（接处警、询问、讯问等） 4. 实现多轮对话上下文管理 5. 集成敏感词过滤 + 等保审计日志

// 警务大模型配置
@Configuration
public class PoliceLLMConfig {

    @Bean
    public ChatModel policeChatModel(@Value("${police.llm.api-key}") String apiKey) {
        return OpenAiChatModel.builder()
            .apiKey(apiKey)
            .baseUrl("https://api.deepseek.com/v1")  // 或国内合规模型
            .modelName("deepseek-chat")
            .temperature(0.3)  // 警务场景低温度，确保准确性
            .maxTokens(2000)
            .build();
    }

    @Bean
    public ChatMemory policeChatMemory() {
        return MessageWindowChatMemory.builder()
            .maxMessages(20)
            .build();
    }
}

验收标准： - 支持警务场景多轮对话（至少 5 轮上下文） - 响应时间 < 3s - 包含等保审计日志

练习2：技战法 Skill 开发

目标：基于 Solon-AI 的 Talents 体系，开发一个警务技战法 Skill。

示例技战法："人员关系分析"

// 人员关系分析 Skill
@Talent("person-relation-analysis")
@Description("分析重点人员的关系网络，识别核心人物和风险团伙")
public class PersonRelationAnalysisTalent implements TalentExecutor {

    @Override
    public TalentResult execute(TalentContext context) {
        // 1. 解析查询参数
        String personId = context.getParameter("personId");
        String relationType = context.getParameter("relationType", "ALL");

        // 2. 调用业务系统接口获取关系数据
        List<Relation> relations = policeDataService.getRelations(personId, relationType);

        // 3. 构建知识图谱
        GraphBuilder builder = GraphBuilder.create();
        relations.forEach(builder::addNode);

        // 4. 分析核心人物（度中心性）
        GraphAnalysisResult analysis = GraphAlgorithms.analyzeCentrality(builder.build());

        // 5. 生成分析报告
        String report = generateReport(personId, relations, analysis);

        return TalentResult.success(report);
    }

    private String generateReport(String personId, List<Relation> relations, GraphAnalysisResult analysis) {
        // 生成结构化分析报告
        return """
            ## 人员关系分析报告

            **目标人员**: %s

            **关系网络规模**:
            - 直接关联人员: %d
            - 关系类型分布: %s

            **核心人物识别**:
            - 度中心性最高: %s (度数=%d)
            - 风险团伙识别: %s

            **研判建议**: %s
            """.formatted(
                personId,
                relations.size(),
                relations.stream().map(Relation::getType).collect(Collectors.groupingBy(r -> r, Collectors.counting())),
                analysis.getTopNode().getId(),
                analysis.getTopNode().getDegree(),
                analysis.getRiskGang(),
                analysis.getSuggestion()
            );
    }
}

验收标准： - Skill 可被 Solon-AI 正确加载和执行 - 支持通过自然语言触发（如"分析张三的关系网"） - 输出结构化报告（Markdown / JSON）

练习3：时空轨迹分析

目标：基于 PostGIS + Solon-AI Flow，实现人员轨迹分析和热点发现。

实现要点： 1. 使用 PostGIS 存储轨迹点（空间坐标 + 时间戳） 2. 基于 Solon-AI Flow 实现轨迹查询编排 3. 支持时空范围查询（某人在某时间段内的轨迹） 4. 实现停留点分析、出行规律识别 5. 热点发现：基于 DBSCAN 聚类算法

CREATE TABLE person_trajectory (
    id BIGSERIAL PRIMARY KEY,
    person_id VARCHAR(64) NOT NULL,
    device_id VARCHAR(64),

练习4：多智能体协同研判

目标：基于 Solon-AI 的 Team Agent，构建多智能体协同研判系统。

智能体分工： - 情报收集 Agent：从多源数据收集相关信息 - 分析推理 Agent：基于知识图谱 + 规则引擎进行分析 - 风险评估 Agent：评估风险等级，生成预警 - 报告生成 Agent：自动生成研判报告

// 多智能体协同研判
@Team("police-analysis-team")
public class PoliceAnalysisTeam {

    @Agent("intel-collector")
    public Mono<String> collectIntelligence(@Variable("target") String target) {
        // 从多源数据收集信息
        return Mono.zip(
            policeApiService.getPersonInfo(target),
            policeApiService.getVehicleInfo(target),
            policeApiService.getCaseInfo(target)
        ).map(tuple -> mergeIntelligence(tuple));
    }

    @Agent("risk-analyzer")
    public Mono<RiskAssessment> analyzeRisk(@Variable("intelligence") String intel) {
        // 基于规则 + 大模型进行风险评估
        return llmService.analyzeRisk(intel)
            .map(result -> RiskAssessment.fromLLM(result));
    }

    @Agent("report-generator")
    public Mono<String> generateReport(@Variable("risk") RiskAssessment risk) {
        // 生成结构化研判报告
        return Mono.just(reportTemplate.render(risk));
    }
}

验收标准： - 多 Agent 协同完成完整研判流程 < 30s - 支持人工介入和干预 - 研判结果可追溯（审计日志）

练习5：业务系统闭环

目标：实现从"咨询问答"到"业务闭环"的跨越，直接操作业务系统。

实现要点： 1. 定义标准化业务接口规范（RESTful API） 2. 基于 Solon-AI Function Calling 实现指令解析 3. 指令执行 + 结果验证 + 自动回写 4. 支持人工审核和撤销

// 业务系统操作接口
@Talent("police-business-operator")
public class PoliceBusinessOperatorTalent implements TalentExecutor {

    @Override
    public TalentResult execute(TalentContext context) {
        String userQuery = context.getUserMessage();

        // 1. 大模型解析用户意图
        Intent intent = llmService.parseIntent(userQuery);

        // 2. 映射到业务操作
        BusinessOperation operation = operationMapper.map(intent);

        // 3. 权限校验
        if (!permissionService.hasPermission(context.getUserId(), operation.getPermission())) {
            return TalentResult.failure("无操作权限");
        }

        // 4. 执行业务操作
        OperationResult result = businessService.execute(operation);

        // 5. 自动回写业务系统
        if (result.isSuccess() && operation.isAutoWriteBack()) {
            businessSystemService.writeBack(result);
        }

        // 6. 生成反馈
        return TalentResult.success(result.getMessage());
    }
}

19.3.3 核心代码示例

示例1：警务大模型 + 业务闭环

@Service
public class PoliceAIService {

    @Autowired
    private ChatModel policeChatModel;

    @Autowired
    private BusinessOperator businessOperator;

    @Autowired
    private TalentRegistry talentRegistry;

    /**
     * 智能研判接口
     * 支持自然语言查询，自动调用业务系统
     */
    public String intelligentAnalysis(String userId, String query) {
        // 1. 意图识别
        Intent intent = recognizeIntent(query);

        // 2. 路由到对应 Skill
        if (intent.hasSkill()) {
            Talent talent = talentRegistry.getTalent(intent.getSkillName());
            return talent.execute(query);
        }

        // 3. 业务操作（需要执行具体业务）
        if (intent.isBusinessOperation()) {
            return businessOperator.operate(userId, query);
        }

        // 4. 普通对话（警务知识问答）
        return policeChatModel.generate(query);
    }

    private Intent recognizeIntent(String query) {
        // 基于 LLM 的意图识别
        String prompt = """
            你是警务智能助手，请分析用户意图。
            用户输入：%s

            请返回 JSON 格式：
            {
                "type": "skill" | "business" | "chat",
                "skillName": "技能名称（如 type=skill）",
                "businessAction": "业务操作（如 type=business）",
                "confidence": 0.95
            }
            """.formatted(query);

        String response = policeChatModel.generate(prompt);
        return Intent.fromJSON(response);
    }
}

示例3：时空轨迹分析

@Service
public class SpatialTrajectoryService {

    @Autowired
    private JdbcTemplate jdbcTemplate;

    /**
     * 查询人员在指定时间范围内的轨迹
     */
    public List<TrajectoryPoint> queryTrajectory(String personId, LocalDateTime start, LocalDateTime end, Polygon area) {
        String sql = """
            SELECT id, person_id, 
                   ST_AsText(location) as location_wkt,
                   captured_at
            FROM person_trajectory
            WHERE person_id = ?
              AND captured_at BETWEEN ? AND ?
              AND ST_Within(location, ST_GeomFromText(?, 4326))
            ORDER BY captured_at
            """;

        return jdbcTemplate.query(sql, (rs, rowNum) -> {
            WKTReader reader = new WKTReader();
            Point point = (Point) reader.read(rs.getString("location_wkt"));
            return new TrajectoryPoint(
                rs.getLong("id"),
                rs.getString("person_id"),
                point,
                rs.getTimestamp("captured_at").toLocalDateTime()
            );
        }, personId, start, end, area.toText());
    }

    /**
     * 停留点分析（基于速度阈值）
     */
    public List<StayPoint> detectStayPoints(String personId, double speedThreshold, Duration minStayDuration) {
        List<TrajectoryPoint> trajectory = queryFullTrajectory(personId);

        List<StayPoint> stayPoints = new ArrayList<>();
        List<TrajectoryPoint> currentCluster = new ArrayList<>();

        for (int i = 0; i < trajectory.size(); i++) {
            TrajectoryPoint current = trajectory.get(i);

            if (i > 0) {
                TrajectoryPoint prev = trajectory.get(i - 1);
                double speed = calculateSpeed(prev, current);

                if (speed < speedThreshold) {
                    currentCluster.add(current);
                } else {
                    if (!currentCluster.isEmpty() && 
                        Duration.between(currentCluster.get(0).getTime(), 
                                        currentCluster.get(currentCluster.size() - 1).getTime())
                            .compareTo(minStayDuration) >= 0) {
                        stayPoints.add(buildStayPoint(currentCluster));
                    }
                    currentCluster.clear();
                }
            }
        }

        return stayPoints;
    }
}

@Team("police-analysis-team")
public class PoliceAnalysisTeam {

    @Agent("intel-collector")
    public Mono<IntelligenceReport> collectIntelligence(@Variable("target") String target) {
        return Mono.zip(
            policeApiService.getPersonInfo(target),
            policeApiService.getVehicleInfo(target),
            policeApiService.getCaseInfo(target),
            policeApiService.getTrajectoryInfo(target)
        ).map(tuple -> IntelligenceReport.merge(tuple));
    }

    @Agent("graph-analyzer")
    public Mono<GraphAnalysisResult> analyzeGraph(@Variable("intel") IntelligenceReport intel) {
        // 构建关系图谱并分析
        return Mono.just(GraphAlgorithms.analyze(intel));
    }

    @Agent("risk-analyzer")
    public Mono<RiskAssessment> analyzeRisk(@Variable("intel") IntelligenceReport intel, 
                                            @Variable("graph") GraphAnalysisResult graph) {
        // 基于规则 + LLM 进行风险评估
        String prompt = riskPromptTemplate.render(intel, graph);
        String llmResponse = llmService.generate(prompt);
        return Mono.just(RiskAssessment.fromLLM(llmResponse));
    }

    @Agent("report-generator")
    public Mono<String> generateReport(@Variable("risk") RiskAssessment risk) {
        // 生成结构化研判报告
        return Mono.just(reportTemplate.render(risk));
    }

    /**
     * 完整研判流程
     */
    public Mono<String> fullAnalysis(String target) {
        return collectIntelligence(target)
            .flatMap(intel -> analyzeGraph(intel)
                .flatMap(graph -> analyzeRisk(intel, graph)
                    .flatMap(risk -> generateReport(risk))));
    }
}

19.4 注意事项

  1. 等保合规：警务系统需满足等保三级要求，数据加密、审计日志、权限控制缺一不可
  2. 数据安全：警务数据敏感，必须脱敏后才能用于模型训练
  3. 国产化要求：优先选择国产大模型、国产数据库，避免供应链风险
  4. 性能优化：时空查询和图计算消耗资源大，需异步处理 + 缓存
  5. Skill 质量：50+ Skill 需经过实战验证，避免"为了数量而数量"
  6. 人机协同：AI 辅助决策，最终决策权在人，设计人工审核和干预机制
  7. 可解释性：研判结果必须可解释，不能是"黑盒"输出
